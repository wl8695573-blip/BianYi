# 公共术语库

本目录保存 边译 可下载的《边狱巴士》术语档案。`limbus-company.ggprofile.json` 是数据，`manifest.json` 记录版本和原始文件的 SHA256。程序随包附带这两个文件；检查更新时读取原仓库 `main` 分支中的同一路径。

## 资料放在哪里

| 位置 | 内容 |
|---|---|
| [中日韩英对照表](MULTILINGUAL.md) | 按人物、称号、组织与地名分类，可直接查阅四语写法、别名和参考。 |
| [四语源数据](multilingual.json) | 维护者编辑的规范名称、别名与逐条来源。 |
| [公共词库](limbus-company.ggprofile.json) | 已发布、随程序附带的术语。 |
| [更新清单](manifest.json) | 客户端核对的词库版本与 SHA256。 |
| [术语库来源与收录](sources/library/) | 独立基础库的整理依据与后续候选资料。 |
| [术语反馈表单](https://github.com/wl8695573-blip/BianYi/issues/new?template=terminology.yml) | 用户向维护者提交补充和纠错。 |

GitHub 用版本管理保存 JSON 词库，客户端直接下载公开数据，无需另设数据库服务器。来源资料的整理与授权记录见 [收录说明](sources/README.md)。

## 用户如何更新

边译 1.5.0 起，在“支持 → 程序与公共词库更新”点击“检查更新”。发现新词库后可手动应用，也可勾选自动应用。启动检查每天最多一次，可以关闭。

主界面“有更新”按钮与悬浮球上的橙色圆点会保留提醒。通过悬浮球菜单也能打开更新页。程序安装包由用户手动下载并启动安装器，词库更新可独立完成。

更新会核对版本、ID 和 SHA256；校验失败不替换已有词库。个人术语，以及已有档案中自行修改、禁用或删除的条目会保留。删除整个档案后不会自动重新添加。保留的个人条目可能与新版公共译名不同，可在术语管理中自行调整。

当前词库版本为 `2026.10.14.1`，共 40 个概念、139 条语言映射，含十二罪人、但丁、维吉里乌斯、卡戎，以及贾环、亚细亚、仇甫、耐莉、亚哈、赫尔曼、狄亚斯、霍恩海姆等人物。另有 8 项色彩相关称号，以及组织、地名和缩写。对照表与程序数据由同一份四语源数据生成。

从 `2026.10.13.1` 起，公共库移除历史内置集合，改为独立整理。中文是维护者选定的译名，不宣称为官方中文或全社区统一译法；不同中文写法在备注中说明。日、韩、英原名参照游戏公开介绍、用户提供的原文画面及公开角色资料，每条记录参考。它不是零协会词库，不包含汉化全文，也不是完整游戏专名表。

软件 1.7.0 会识别旧版未修改条目的指纹，替换或移除这些历史默认数据；用户改变的译名、禁用条目和个人术语保留。指纹中没有旧词库文本。旧客户端可以通过已有的词库更新功能接收新版；建议同时升级软件以覆盖没有公共基线记录的旧配置。

## 维护者如何发布词库

1. 按 [术语贡献说明](../CONTRIBUTING.md) 核对反馈。编辑 `multilingual.json`：每个概念只建一条记录，填写唯一 `id`、分类 `category`、`zh`／`ja`／`ko`／`en` 四语规范写法、备注 `note` 与公开参考 `sources`。称号和姓名分开。不确定的内容先放入候选区，不要为凑齐四语猜写。
2. `aliases` 按 `ja`、`ko`、`en` 保存已核对的旧写法或拼写变体。中文规范名是跨语种转换的桥梁，同一概念只选一个；中文异译在备注中说明。导出时别名在前、规范写法在后，保证反向翻译和外语互译选用规范名。
3. 增加源数据的 `version`，如 `2026.10.14.1` → `2026.10.14.2`。在仓库根目录运行以下命令，生成客户端档案、校验清单和四语对照表。不要直接编辑生成的 `profile.terms` 或对照表。

```powershell
dotnet run --project tools/TermLibrary -c Release -- terminology --from-multilingual
dotnet run --project tools/TermLibrary -c Release -- terminology --check
```

4. 将源数据、对照表、词库与清单放在同一个提交中，推送到 `main`。GitHub Actions 会检查版本、SHA256、四语数据和生成文件是否一致。只有需要改动程序时才另外打包 Release；公共词库更新不要求重新发布程序。每次实际更改发布数据都要增加版本号，不能复用旧版本。
5. 核对 GitHub 原始文件中的版本与哈希，再在反馈 Issue 中回复版本和获取方法。网络缓存可能短暂保留旧版本，可稍后再次检查。

`.gitattributes` 禁止 Git 改写这两个 JSON 的换行，确保下载内容与 SHA256 一致。不要只修改清单而不核对数据。

工具不加 `--from-multilingual` 时保留客户端档案内容，只重写版本与校验清单。四语源数据存在时，发布版本必须与它一致。`--from-code` 仅供恢复嵌入档案，不是日常维护步骤。

```powershell
dotnet run --project tools/TermLibrary -c Release -- terminology --from-code
```

程序重新打包时包含当前 JSON，因此新版安装后的公共基线也随之更新。应用更新时继续保留个人修改；导入第三方或自建档案仍采用独立副本。
