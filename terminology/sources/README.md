# 术语来源与收录资料

这里保存维护者收到的术语资料、来源说明和使用记录。[术语库](library/) 已接入独立基础库，后续资料的提供方和出处在库内填写。

## 目录与用途

| 路径 | 用途 |
|---|---|
| `library/source.json` | 来源、授权范围、署名要求和资料版本。 |
| `library/terms.json` | 收到并整理后的候选术语，当前为空。 |
| `../multilingual.json` | 已核对的中、日、韩、英规范名、别名和参考。 |
| `../MULTILINGUAL.md` | 从四语源数据生成的分类对照表。 |
| `../limbus-company.ggprofile.json` | 客户端实际使用的公共术语库。 |
| `../manifest.json` | 公共词库的发布版本和 SHA256。 |

`sources/` 是收录资料区，客户端不会读取或打包这个目录。维护者确认授权和条目后，将允许发布的内容合并到公共词库。这样收到的资料可以保留原始版本，公开词库也能统一处理重复、纠错和个人修改。

## 收录流程

1. **收到资料。** 提供方的术语资料整理到术语库内，填写来源；用户建议通过 [术语反馈表单](https://github.com/wl8695573-blip/BianYi/issues/new?template=terminology.yml) 提交。用户也可以把原文、译名和出处直接发给维护者。
2. **核对来源。** 确认资料是否允许在公开仓库中保存、随安装包分发和在线更新，填写来源记录。授权邮件原件可以由维护者私下留存，公开使用范围与署名要求即可。
3. **核对条目。** 确认语言、原文、译名和适用场景；按“语言＋原文”查找已有条目。同义条目合并，冲突译名先核对，未确认的内容暂不启用。
4. **发布。** 将确认的条目写入四语源数据，增加版本并导出公共词库、对照表和校验清单，一起推送到 `main`。命令见 [词库维护说明](../README.md#维护者如何发布词库)。
5. **告知用户。** 在对应反馈中回复结果、词库版本和更新方法。现有用户可检查词库更新；以后发布的安装版和便携版会附带打包时的公共词库。

只有修改来源资料或文档时，无需提高公共词库版本。只把文件放进本目录不会触发客户端更新。

## 授权与署名

项目代码的 MIT 许可不替代术语资料提供方的许可。第三方资料按其允许的用途使用；如果仅允许私人使用，就不能放进公开仓库或随程序分发。不要把未取得允许的完整汉化文本、截图合集或私人邮件放在这里。

独立公共库的依据已记录在各条目中，候选资料文件当前为空。后续第三方资料收到后再填写提供方，确认使用条件后收录。
